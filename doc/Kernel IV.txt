Kernel Aufbau und Design IV: Kernel III + Protokoll vom 09.06.06


1. Vorwort

Dieses Dokument beschreibt Design des Kernels.
Es wurde geschrieben von Toaster. (am 10.06.2006)


2. Generelles

Gebildet wird der Lost Kernel duch den den Kernel Kern, Core gennant, und durch Kernel Module,
der einfachheit nur Module gennant.
Der Core beinhaltet alle wichtigen statischen Teile des Kernels, und ist zu einer
Datei zusammengefasst.
Kernel Module sind, wie der Name schon sagt, Module die Kernel Funktionen übernehmen/implementieren.
Dies sind im allgemeinen Treiber.
Sie sollen weitestgehen unabhängig von einander sein, um die Ausfallsicherheit zu erhöhen.
Sobald ein Modul ausfällt (Fehler usw.) gibt es ein vordefiniertes Verhalten damit das
System nicht (ohne zumindest Daten zu sichern) abstürzt.


3. Speicherbelegung

3.1 physikalisch

Physikalisch hat der Speicher 2 reservierte Felder:
  - 640 KB bis 1 MB
  - letzten 512 MB (v.a. wegen VESA Linearen Frame Buffer)

Das erste Speicherfeld darf nicht angesprochen oder beschrieben werden, da sich dort das BIOS
(heutzutage Flash) befindet.
Das zweite Speicherfeld ist nur bedingt reserviert, hier befinden sich Dinge die in den
physikalischen Speicher hineingemappt sind, wie z.B. der VESA Frame Buffer oder der APIC.
Ansonsten gibt es (theoretisch) keine Festlegungen, alle Pages werden dynamisch und
flexibel vergeben.
Die Speichereinteilung und Vergabe erfolgt immer in 4 KByte Pages.

3.2 virtuell

Der Kernel memory wird im virtuellen Adressraum (auch VAS genannt) von 3 GB bis 4 GB
untergebracht, also in den oberen 1 GB.
Die Startadresse ist somit 0xc0000000.
Fix festgelegt ist dass der Kernel memory durchgehend PL0 hat, während der gesamte andere
virtuelle Speicher ohne Ausnahme PL3 besitzt.


4. Implementierung des Cores

Folgende Teile werden als Core zusammengefasst:

- Memory Manager
- Task Switcher
- IPC

Der Core befindet sich statisch (in Gegensatz zu den Modulen) an einer statischen Adresse,
0xc0000000, welche der Beginn des Kernel memorys ist.
Der Core besitzt kein Format oder Header.

Funktionen des Cores (bzw. der einzelnen Teile) werden per Interrupts aufgerufen.
Dabei werden die Interrupts 80h für den Memory Manager, 81h für den Task Switcher und
82h für den IPC verwendet.


5. Implementierung von Modulen

Jedes Module besteht aus einer seperaten ausführbaren Datei.
Dabei bekommt jedes Modul einen Task zugewiesen, weil die Kommunikation mit Modulen in Lost
auf IPC basiert.
Es gibt keine definierte Liste von Modulen, alle Module werden dynamisch verwaltet und es
können auch Module flexibel hinzugefügt werden.

Jedes Modul muss eine Funktion besitzen welche das Modul initialisiert, ihr Name ist "entry".
Der einzige übergebene Parameter ist ein Handle (dword), womit das Modul weitere Strukturen
abrufen kann. (z.B. verschiedene Handles)
Damit das System weiß wo sich die Funktionen (wie entry) befinden, gibt es auch ein Format,
welches vorläufig das elf-Format ist.


6. Kernel memory

Außer dem Core gibt es keine festgelegten Belegungen des Kernel memorys.
Der gesamte Speicher wird dynamisch vergeben und verwaltet.
